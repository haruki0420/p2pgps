# カーナビ用途での適性

P2P GPS を車載ナビの位置ソースとして使えるかを、プロトコル・実装・実機構成の観点で整理します。

## 結論

- **カジュアルなナビ（現在地確認・ルートの目安・同乗者向け表示）**: 実用範囲です。
- **車線案内・安全運転支援・自動運転など、遅延や誤差が安全に直結する用途**: 不適です。
- 実用上の推奨は **500 ms（2 Hz）+ Extended Location 有効**、両端末を給電し、Android の電池最適化を無効化することです。

## 仕組みと遅延

```
iPhone/Android の GPS
  → BLE notify（20 bytes、MTU 23 でも分割不要）
  → iPad の FixFilter（外れ値除去 + 平滑化）
  → 位置シミュレーション（simulate_location）
  → ナビアプリ
```

| 要素 | 目安 |
| :--- | :--- |
| GPS fix の更新 | 1 Hz 前後（端末・屋内/屋外で変動） |
| BLE notify | 接続間隔にもよるが数十 ms |
| FixFilter の平滑化 | `smoothingFactor = 0.5` で 1 fix あたり半分だけ追従（遅れの主因） |
| 位置シミュレーション | 受理ごとに反映。再送は 5 秒間隔（失敗時の維持用） |
| 体感遅延 | おおむね **0.5〜1.5 秒** |

時速 60 km/h では 1 秒で約 16.7 m 進むため、1 Hz のままだと **8〜25 m 程度の遅れ**が見込まれます。2 Hz にすると遅れは半分程度になります。

## 精度

- スマートフォンの GPS は **±5〜20 m** 程度。カーナビの「車線」レベルではありません。
- 都市部のビル、高架下、トンネル、地下駐車場では誤差・欠測が増えます。
- P2P GPS は死測（ジャイロ・車速パルス）を行わないため、GPS が途切れると最後の位置のまま止まります。

## 推奨設定

| 項目 | 推奨 | 理由 |
| :--- | :--- | :--- |
| 送信間隔 | **500 ms（2 Hz）** | 1 Hz より追従が滑らか。BLE 負荷も実用範囲 |
| Extended Location | **ON** | 速度・進行方向・垂直精度を送れる |
| 位置情報を反映 | ON | 当然必要 |
| Android の電池最適化 | P2P GPS を対象外 | 前景サービス停止を防ぐ |
| 両端末の給電 | 必須 | 画面 ON + GPS + BLE で消費が大きい |
| 他の VPN | 切断 | LocalDevVPN と競合する |
| iPad の画面 | ON のまま | バックグラウンド維持は補助であり保証ではない |

## 実機で確認するときの観点

1. ナビアプリ（Apple マップ / Google マップなど）で現在地が動くか
2. 交差点を曲がったときの追従遅れ（1 Hz と 2 Hz を比較）
3. トンネル・高架下で止まらないか
4. 10〜15 分走行して Android の通知が消えないか（電池最適化）
5. iPad が熱で画面を暗くしないか（夏場は特に注意）

## 既知の制約

- iOS の位置シミュレーションは Apple の非公開サービスに依存します。OS アップデートで壊れる可能性があります。
- BLE は 1 対 1 接続です。iPad と送信端末を近距離（同じ車内）に置いてください。
- pairing file / DDI / LocalDevVPN のセットアップが必要です。
- 本アプリは安全運転支援・自動運転・車線維持を目的とした認証製品ではありません。運転中の操作は同乗者が行ってください。
